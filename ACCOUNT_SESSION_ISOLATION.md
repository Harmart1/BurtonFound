# Account session isolation

Account hydration captures identity and a generation, cancels delayed cart writes when identity changes, and checks generation after each awaited import before updating state or starting another write. Recovery sessions do not load customer tables or merge guest records; ordinary authenticated token use is disabled during recovery. Private account cart is in memory and server-side, not the shared browser guest cart. New guests retain a separate `bf_guest_active_bag_v2` cart. The legacy mixed browser cart is deliberately not migrated because it might belong to a previous signed-in customer; an unsynchronized legacy bag may need to be recreated, but server-saved carts and actual orders are untouched. Delayed stale account history responses cannot render in another session. Existing Supabase row-level security is still essential; this change is a client-side safeguard, not a replacement for server authorization. Already-dispatched requests cannot be canceled by this change; RLS remains authoritative. Browser fixtures and unit tests do not prove cross-tab delivery, real email or live account behavior. No live account credentials, data, payments or tax settings changed.
