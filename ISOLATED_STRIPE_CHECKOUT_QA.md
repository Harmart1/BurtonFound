# Isolated Stripe checkout QA

Two independent layers: the local test uses actual checkout, webhook and status handlers with repository migrations in an ephemeral PostgreSQL 17 service and synthetic provider responses. It covers price authority, holds and overlap, delayed payment, expiry/release, confirmed payment and duplicate signed events, order totals and public order status. No production database or secrets are accessible to this job.

The explicit main-only provider job uses the verified test key, checks the deployed public preview gate and signed isolation probe before creating anything, refuses unexpected enabled sandbox webhook destinations, and marks its synthetic Checkout Session, PaymentIntent and refund. The production webhook acknowledges only marked test Checkout events without database writes; live events cannot use this path. Provider QA creates an actual test-mode hosted Checkout Session and expires it, then separately confirms a test PaymentIntent with Stripe's test PaymentMethod and requests a test refund. No real money, customer email or real inventory. Test dashboard records may remain, and an ambiguous network failure can leave a synthetic open session until expiry. No raw API objects or keys in logs. The provider job is never automatic on ordinary commits or PRs. Run it only after deploying the guard and owner-authorized test mode.

The two layers together are not proof of a paid hosted Checkout customer journey, receipt delivery, production tax, actual carrier rates or real-money settlement. Complete a separately approved hosted Checkout test against isolated stock and a real inbox before enabling live checkout. No approval flags are changed.
