# Burton & Found — Canada + United States live carrier-rate rollout
**Implementation date:** November 25, 2026  
**Status:** Code prepared and unit-tested; merchant accounts, real parcel measurements and live-carrier quotes **not enabled**; customer payments **disabled**.

## Architecture now in GitHub

- Current Cloudflare Worker `burtonfound` stays as the host; no migration to Pages or GitHub Pages.
- `functions/_lib/canada-post-json.js`: Canada Post Developer Portal Rating v4, OAuth 2.0 with Basic-auth token exchange, JSON POST `/rating/v1/prices`, parses the official top-level JSON array and `priceDetails.due` CAD field. Uses the documented origin postal code `P6A1Z1`, packed kilograms / centimetres and Canadian or U.S. destination.
- `functions/_lib/shipping.js`: default Canada Post mode `json`; optional explicit `legacy` XML compatibility only with older credentials. FedEx OAuth Rates & Transit Times integration remains. Both carrier adapters require genuine accounts; no fallback made-up rates.
- `functions/api/shipping-quotes.js`: 10-minute HMAC-signed choices with amount, country, destination, SKU set, packed weight/dimensions and mailing date. **Never publishes Canada Post Test-app or FedEx Sandbox stub prices**. If neither real rate provider returns an option, returns a clear 503 instead of a guessed shipping price.
- `functions/_lib/shipping.js` additionally blocks U.S. payment checkout until the cross-border and (for Canada Post) duty-declaration workflow have been explicitly approved. Separate carrier production-verification gates prevent a live-money checkout from relying on unvalidated carrier rates.
- Storefront ships to Canada/U.S. only, with a customs/duties disclaimer; UI adds the actual selected rate to the item subtotal only when a carrier quote is available.
- The new `npm run shipping:worksheet` creates `marketing-output/shipping-measurements-to-complete.csv` with all 229 catalogue SKUs plus any preserved existing custom rows. It **never invents weight, dimensions or stock availability**. Deployment attaches this worksheet to the downloadable marketing release artifact.

## First: Merchant actions required

1. Create a Canada Post Solutions for Small Business or commercial account, confirm the customer number, and register a **Test** and later a **Production** app subscribed to the new [Rating API](https://developer-developpeur.canadapost-postescanada.ca/devportal-portaildesdeveloppeurs/api/overview/rating). Obtain its client ID and client secret. Do not use the old XML username/password in the new JSON integration.
2. In [FedEx Developer Portal](https://developer.fedex.com/api/en-us/catalog/rate.html), create a Ratings & Transit Times project and associate the actual Canadian shipper account number. Obtain test credentials first, then production credentials with permissions for domestic Canada and Canada-to-U.S. rates.
3. **Physically pack representative pieces** in protective sleeves, rigid backing and mailers; weigh the **packed** parcels and measure the three exterior dimensions. Complete the generated CSV for each eligible SKU. Multi-item carts require a separately measured combined-parcel row with SKUs alphabetically joined by `+` (for example `CC-010+OH-003`). No inferred package dimensions.
4. Review and confirm saleable physical stock and verified product descriptions. The photographed vintage automobile catalogue remains enquiry-only until physical originals are inventoried in Supabase. No carrier integration can verify ownership or stock.
5. For U.S. deliveries, document actual customs classifications, country of manufacture/origin, declared unit values, who pays duties/taxes and carrier brokerage, and the agreed fulfillment procedure. **Canada Post U.S. parcels require a Zonos/Declaration ID workflow** before shipping; a postal rate quote is not a customs-duty quote.

## Cloudflare Worker settings (never enter private keys into GitHub)

Go to **Cloudflare → Workers & Pages → burtonfound → Settings → Variables and Secrets**. Set encrypted *secrets* for:
- `CANADA_POST_CLIENT_ID` and `CANADA_POST_CLIENT_SECRET` (new portal app, Test app first)
- `FEDEX_CLIENT_ID`, `FEDEX_CLIENT_SECRET`, `FEDEX_ACCOUNT_NUMBER`
- `SHIPPING_QUOTE_SECRET`: random, at least 32 characters; keep private
- Existing Supabase/Stripe credentials remain separate and must never be logged or committed

Set ordinary configuration for:
- `SHIPPING_MODE=live_carrier` only when ready to test authentic quotes (site currently `flat_rate`)
- `SHIPPING_ALLOWED_COUNTRIES=CA,US`
- `CANADA_POST_API_MODE=json`
- `CANADA_POST_CUSTOMER_NUMBER=<actual merchant number>`; `CANADA_POST_CONTRACT_ID` only if a real contract applies
- `SHIPPING_PACKAGES_JSON` generated by `python scripts/build_shipping_packages.py SHIPPING_PACKAGE_MEASUREMENTS.csv` after actual measurements and owner confirmation
- `SHIPPING_HANDLING_BUSINESS_DAYS=2` or another honest merchant-approved handling estimate
- `CANADA_POST_TEST_APP=true` and `FEDEX_SANDBOX=true` while using test apps. These suppress publicly shown test/stub rates.
- Only after account-specific **production** carrier rate tests pass, switch `CANADA_POST_TEST_APP=false` and/or `FEDEX_SANDBOX=false`, and approve the corresponding `CANADA_POST_PRODUCTION_VERIFIED=true` or `FEDEX_PRODUCTION_VERIFIED=true`. Do not enable untested carriers.
- `US_SHIPPING_APPROVED=false` and `CANADA_POST_US_DUTIES_APPROVED=false` until compliance, duty payment and fulfillment have been verified. A U.S. postage estimate does *not* include customs duties, destination taxes or brokerage.

**Currently leave these as `false`:** `CARRIER_QUOTES_ENABLED`, `LIVE_CHECKOUT_ENABLED`, `LIVE_PAYMENTS_APPROVED`, `TAX_CONFIGURATION_APPROVED`, `MARKETING_INDEXING_APPROVED`. When genuine quotes are verified, `CARRIER_QUOTES_ENABLED` can be enabled in a controlled deployment independently of live payments. Current GitHub deployment intentionally checks that payment and carrier flags are disabled; do not manually flip a flag without coordinating this workflow and `wrangler.jsonc`.

## Verify in order, using real account test credentials

1. Run `npm run shipping:worksheet`, confirm each measured package's actual exterior dimensions and signed seller approval; produce the JSON for only verified rows.
2. Test `canadaPostJsonRequest`, `parseCanadaPostJson`, FedEx rate parsing and the signed quote and tamper tests with `npm test` in GitHub CI. These are mocked checks, **not proof of customer-account live prices**.
3. Authenticate against both carriers' test services and inspect returned schema/currency without printing credentials. **Canada Post Test applications return stubbed responses**, so do not publish them as authentic postage.
4. Confirm production credentials by retrieving actual Canada and U.S. account-specific service quotes for a **real, measured** single item and curated set. Compare quotes directly in each carrier dashboard for the same parcel/date/destination, including tax/surcharges.
5. Test Sault Ste. Marie → Toronto, remote Ontario, Vancouver, Ottawa, New York, California and a remote U.S. ZIP code. Ensure any unavailable service simply disappears, without invented prices.
6. Requote after changes to the address, cart, parcel profile or quote expiration; reject altered HMAC tokens.
7. Confirm that `US_SHIPPING_APPROVED=false` still blocks U.S. paid checkout. Confirm the Canada Post Declaration ID / duty payment workflow and FedEx brokerage responsibilities before approval.
8. Complete Stripe **test-mode** orders and verify the shipping selection, order database and webhook. Review any address mismatch before fulfilment. Only then discuss live money (this release leaves it disabled).
9. Note: buying labels, collecting duties, carrier scans and refund synchronization are **not automated** by this rating-only integration. Seller still purchases labels and enters tracking through the owner orders dashboard.
