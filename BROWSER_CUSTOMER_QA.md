# Synthetic customer journey QA

Browser QA exercises the current production HTML, styles and scripts in Chromium at desktop (1440x900) and mobile (390x844) viewports. A localhost-only fixture serves a mock account and stock service and mimics Cloudflare's /account.html to /account redirect. All external network traffic is aborted at the browser context; all HTTP write requests are rejected by the fixture. No production email, payment, registration, stock reservation, customer data or password is touched. The synthetic credentials are not real.

Scenarios: signup and neutral confirmation message, forgot password, resend confirmation, valid recovery callback from homepage, password mismatch, password change and sign-in, invalid credentials, normal customer cannot access owner UI, expired links, product detail, guest bag. Browser checks are separate from live read-only account/stock health checks. The tests use a mock SDK and cannot prove SMTP receipt, live Stripe/carrier behavior, or real customer account persistence. Browser QA is scheduled weekly and on relevant changes. Production launch still requires owner-controlled inbox confirmation and reset, carrier and Stripe credentials, measured packaging and stock verification.
